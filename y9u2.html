Complete revision notes

The main checklist skills come first, followed by extra content from your scheme of work.

1. AND, OR and NOT gates

Boolean logic uses just two states: 1 (true) and 0 (false). Each gate produces an output from its input(s). A small circle after a symbol means NOT or inversion.

ABA AND BA OR B
0000
0101
1001
1111

NOT: 0 becomes 1, and 1 becomes 0. In a multi-gate circuit, work from inputs to output, noting intermediate results.

2. Binary numbers and converting bases

Computers use binary because electronic circuits can reliably distinguish two states. Denary uses base 10, while binary uses base 2.

Bit position76543210
Place value1286432168421

Binary → denary: add place values wherever a 1 appears. Example: 00110100 = 32 + 16 + 4 = 52.

Denary → binary: choose the largest place value that fits, subtract it, and continue across the columns. Example: denary 74 = 64 + 8 + 2, so eight-bit binary is 01001010.

Hexadecimal extension: base 16 uses 0–9 and A–F. Every hexadecimal digit maps to four bits. Example: denary 46 = hex 2E.

3. Binary addition, carries and overflow

Work from right to left, exactly as with column addition. In binary: 1 + 1 = 10, so write 0 and carry 1. If adding two bits and a carry, 1 + 1 + 1 = 11, so write 1 and carry 1.

   0111   (7)
 + 0011   (3)
 -------
   1010  (10)

Overflow: if the result needs an extra bit beyond the available unsigned bit width, the correct sum cannot be represented. Four unsigned bits hold 0–15; for example 14 + 5 = 19 needs five bits.

4. Flowchart symbols and decisions

A flowchart represents an algorithm using standard shapes. Use arrows to show direction and label decision paths clearly.

OvalStart or stop (terminator).
RectangleA process, e.g. calculate total.
DiamondA question with branches.
ParallelogramInput or output a value.
Flow arrowsThe order to follow.
LoopAn arrow that returns to repeat.

To dry run a flowchart, substitute a sample input, follow only the path that matches its conditions, and record the final output. Test both sides of each decision.

5. Success criteria and algorithm design

Success criteria state what a solution must demonstrably do. A vague statement such as “the system is good” is not easily testable. A clearer criterion is “when fewer than four theatre seats remain, display an availability warning”.

An algorithm has clear, ordered steps. Plan the inputs, decisions, processes and outputs. Include boundary values when testing, such as just below, equal to and just above a threshold.

6. Pseudocode and comparison operators

Pseudocode uses structured English and programming-like words to explain an algorithm without following the exact syntax of a language. Use meaningful names and consistent indentation.

INPUT score
IF score >= 12 THEN
    OUTPUT "Challenge unlocked"
ELSE
    OUTPUT "Keep practising"
ENDIF
OperatorMeaning
>Greater than
<Less than
>=Greater than or equal to
<=Less than or equal to
==Equal to (comparison in Python)
!=Not equal to

Some pseudocode styles use a single = for equality; in Python, a single = is assignment and == is equality comparison.

7. Storage units and common errors (extension)

One byte is eight bits. Common storage units increase from byte → KB → MB → GB → TB. Do not confuse a bit (b) with a byte (B).

  • Logic: OR means one or both inputs may be 1.
  • Binary: the rightmost column is 1, and values double to the left.
  • Flowcharts: a diamond tests a condition; a rectangle performs an action.
  • Pseudocode: use a loop for repetition, not a huge block of repeated lines.
You should be able to show working for binary calculations and explain why each flowchart choice or gate output is correct. Knowing a word alone isn't enough.
