01

Units & binary numbers

Bits, bytes, storage units, place values, conversions and unsigned range

Why binary?

Computers represent information using two states: 0 and 1. A bit is one binary digit. Binary is base 2, so each place value is twice the value of the place immediately to its right.

Bits, nibbles and bytes

1 bit = one 0 or 1. A nibble = 4 bits. A byte = 8 bits. A byte can represent 2⁸ = 256 different patterns.

Storage units

For this unit, use decimal storage units: 1 kB = 1,000 bytes; 1 MB = 1,000 kB; 1 GB = 1,000 MB; 1 TB = 1,000 GB; 1 PB = 1,000 TB. Eight bits make one byte.

Binary place values

The eight columns, from LEFT to RIGHT, are 128, 64, 32, 16, 8, 4, 2 and 1. Add the values of columns containing a 1 to convert binary to denary.

Denary into binary

To represent a denary whole number, work from the biggest place value down. Place a 1 where the value fits, subtract it, and put a 0 where it does not. Pad to eight bits where asked.

Unsigned integer limits

With n bits, there are 2ⁿ combinations and the unsigned range is 0 to 2ⁿ − 1. An eight-bit unsigned number therefore has a maximum value of 255.

Significance and parity

The leftmost bit of an unsigned byte is the most significant bit (MSB); the rightmost is the least significant bit (LSB). An unsigned binary number ending in 1 is odd; ending in 0 is even.

Exam method

Show your place values, state whether you are working with a fixed number of bits and check that your answer fits the allowed unsigned range.

HEX

Binary arithmetic & hexadecimal

Base 16, four-bit nibbles, addition, overflow and logical shifts

Hexadecimal is base 16

Hex uses 0–9 and A–F, where A = 10, B = 11, C = 12, D = 13, E = 14 and F = 15. One hex digit represents exactly four bits, making long binary values easier to read.

Binary to hex

Split an eight-bit binary value into its two four-bit nibbles. Convert each nibble separately into one hexadecimal digit. Keep leading zeroes when an eight-bit answer is required.

Hex to binary

Translate each hexadecimal digit into exactly four binary bits, even if it starts with zero. Join the nibbles to make an eight-bit number.

Hex and denary

For two-digit hex XY: multiply the left digit by 16 and add the value of the right digit. For denary to hex, divide by 16 and use the quotient and remainder.

Binary addition

Start at the RIGHT-hand column. 0 + 0 = 0; 0 + 1 = 1; 1 + 1 gives 0, carry 1; 1 + 1 + carried 1 gives 1, carry 1. Work through the bit columns carefully.

Overflow

An unsigned eight-bit result can hold at most 255. If an addition produces a ninth bit, there is an overflow because the result cannot fit in eight bits.

Logical shifts

Move all bits left or right by the stated number of columns, filling emptied positions with zero. Bits pushed off the edge of a FIXED-width word are lost.

Shift effects

A left logical shift by one doubles an unsigned value only if no significant 1 is lost. A right shift divides by two and discards remainders, so the result rounds down.

Common trap

A hexadecimal value such as 1A is one hexadecimal number, NOT two denary digits. Calculate 1 × 16 + 10 to convert it to denary.

Aa

Representing characters

ASCII, extended ASCII, Unicode, codes and text storage

Characters are encoded as numbers

A character set maps letters, digits, spaces and symbols to numerical codes. Those numbers can be stored in binary. The uppercase and lowercase forms of a letter have different codes.

Standard ASCII

Original ASCII uses 7 bits and can represent 2⁷ = 128 different codes. It includes English letters, digits, spaces, punctuation and control characters.

Extended ASCII

An eight-bit extended ASCII encoding provides 2⁸ = 256 possible codes. Different extended encodings may use the additional codes differently.

Unicode

Unicode provides a much wider character repertoire for many languages and symbols, including emoji. Unicode is a character standard, NOT a single fixed bits-per-character storage format: encodings include UTF-8 and UTF-16.

ASCII number characters

The ASCII code for the character '0' is 48 and for '9' is 57. These are not the same as the numerical values zero and nine. The code for 'A' is 65 and 'a' is 97.

How many characters?

A set of n-bit fixed-length codes has 2ⁿ possible patterns. Increasing from 7 bits to 8 bits doubles the number of possible distinct codes.

Text file sizes

For exercises assuming one 8-bit code per character, each character needs one byte. Spaces and punctuation count too. Unicode text may use different numbers of bytes depending on the encoding and characters.

Useful exam comparison

ASCII needs fewer codes and represents a limited range of characters. Unicode can represent a far wider range of characters and languages; storage size depends on the encoding.

▦

Representing images

Bitmap pixels, resolution, colour depth, file sizes and metadata

Bitmaps and pixels

A bitmap image is made of a grid of coloured pixels. Each pixel has a binary value representing its colour. Bitmap images can be edited by changing these values.

Resolution

Resolution can be given as width × height in pixels. More pixels provide more image detail but increase uncompressed file size when colour depth stays the same.

Colour depth

Colour depth is the number of bits used to represent each pixel. With n bits per pixel, up to 2ⁿ different colours can be represented. More bits per pixel normally give more possible colours and a larger uncompressed file.

Image size formula

Uncompressed bitmap size (bits) = width × height × colour depth. Divide the result by 8 for bytes. The calculation ignores metadata, headers, padding and compression.

Monochrome bitmaps

At one bit per pixel, the two available bit patterns are 0 and 1. You can represent a black-and-white grid with one binary digit for each pixel.

RGB colour

A common 24-bit RGB pixel stores 8 bits each for red, green and blue. Each component can represent values from 0 to 255, providing 2²⁴ possible combinations.

Alpha channel

A 32-bit RGBA pixel often includes 8 extra bits for transparency (alpha), in addition to 24 bits of RGB colour.

Metadata

Image metadata is information about the file, such as dimensions, colour depth, creation date or author. File headers and metadata explain why a stored file may be larger than the simple raw-pixel calculation.

Bitmap versus vector

Bitmap formats include BMP, PNG and JPEG. SVG is a vector format describing shapes mathematically rather than storing a colour value for every individual pixel.

♫

Representing sound

Analogue sound, sampling, ADC and DAC, rate, bit depth and file size

Analogue versus digital

An analogue sound wave changes continuously. A computer stores a digital representation made from discrete measurements called samples.

Analogue-to-digital conversion

An ADC measures the analogue input and turns each sample into a digital value. A DAC converts digital values back into an analogue output signal for playback.

Sample rate

The sample rate is the number of sound measurements taken each second, measured in hertz (Hz). For example, 8,000 Hz means 8,000 samples each second.

Audio bit depth

Bit depth is the number of bits used to store EACH sample. Higher bit depth allows more possible amplitude values and finer measurement of the wave height.

Sound file size

Uncompressed audio size (bits) = sample rate (Hz) × bit depth × duration (seconds) × number of channels. For mono audio the number of channels is one; convert bits to bytes by dividing by eight.

Quality and size trade-off

Increasing sample rate captures more points across time. Increasing bit depth provides more amplitude levels. Both increase uncompressed file size.

Why compression matters

Uncompressed audio can be large. Lossy formats such as MP3 remove some information to save space; lossless formats such as FLAC preserve the data when decompressed.

Common trap

Do not confuse sample rate (measurements per second) with bit depth (bits per measurement) or bit rate (bits transmitted per second).

ZIP

Compression

Lossy versus lossless, RLE and dictionary ideas, streaming and file formats

Purpose of compression

Compression reduces a file's size so it needs less storage space or fewer bits to transmit. This can reduce download time and make streaming more practical.

Lossy compression

Lossy compression permanently discards some original information. A decompressed file is not identical to the original. JPEG photographs and MP3 sound are common examples.

Lossless compression

Lossless compression allows the original data to be reconstructed exactly. It is important for software, documents and any information where losing bits would cause problems.

Run-length encoding

RLE represents consecutive repeated values as a count plus the value, such as AAAA → 4A. It works well on long runs but can make data larger if there are few repetitions.

Dictionary-based compression

Repeated patterns can be stored in a dictionary and referred to using shorter codes. The decompressor uses the same pattern definitions to rebuild the original.

Lossy artefacts

Image or video compression may cause visible blocks, blurred edges or other artefacts; sound compression can reduce detail. The severity depends on the settings.

Formats to recognise

JPEG is normally lossy; PNG, GIF and ZIP are lossless; MP3 is lossy; FLAC and ALAC are lossless. A file extension alone does not describe every possible compression detail.

Streaming and buffering

Streaming services use compression to reduce the rate of data needed. If data arrives more slowly than it is played, buffering may occur. Lower-quality streams require less bandwidth.

Choose the method

A program file must be restored exactly, so use lossless. A photo or music stream may tolerate some loss of detail to reduce the amount of data transferred.
