🔍 Think like a programmer

Prediction challenge

If the store-room light level is 20 but no movement is detected, what happens to the lamp? Why?

Reveal explanation

It stays OFF. Both conditions must be true, not just one.

Safety challenge

What should the car park controller do if its barrier obstruction sensor stops working?

Reveal explanation

It should avoid unsafe movement, warn an operator and use a safe fallback. A real barrier also needs additional safeguards.

Seven-Segment Display Lab

A seven-segment display contains seven controllable parts, labelled a to g. Click the segment letters to light them up and try to create a target digit.

Target digit

How are displays controlled?

Each segment is an output that can be switched ON or OFF by the controller. The correct combination makes a recognisable number.

To show spaces remaining in a control system, the programme checks a counter variable and chooses the right display pattern.

A seven-segment display can normally represent a single digit from 0 to 9. If the stored number needs more digits, the system needs extra display positions.

Your full revision guide

Year 8 Flowol Revision Notes

Work through the notes in order, or use the headings to focus on a topic.

Lesson 1

1. Control systems and flowcharts

A control system uses inputs (such as sensors) to make decisions and produce outputs (such as a motor or light).

Common flowchart symbols: oval = START/STOP; rectangle = process; diamond = decision; parallelogram = input/output; arrow = direction of flow.

A correct sequence matters. A flashing output must include ON, a pause, OFF and a pause, then repeat.

Lesson 2

2. Sequencing, loops and reliability

A sequence is the order of instructions. A loop repeats instructions. Delays control how long a system waits.

Two outputs that must work together need careful synchronisation. Timed systems do not automatically react to unexpected changes in their environment.

A faulty sensor, loose wire or wrong instruction can create a dangerous malfunction. Always consider a safe fallback.

Lesson 3

3. Sensors and decisions

Sensors detect changes, such as temperature, light, movement or a pressed switch. Their readings become inputs to a controller.

Decision diamonds test a condition, for example temperature > 26. The system follows the Yes or No path.

Be precise: > means greater than and < means less than. A value equal to the threshold does not satisfy either of these strict comparisons.

Lesson 4

4. Subroutines and modular programming

A subroutine is a reusable group of instructions. When a programme calls a subroutine, the instructions run and control returns afterwards.

For a display that makes a short warning sound, you might create one BeepOnce subroutine and call it each time the warning is needed.

Advantages: less duplicated code, clearer flowcharts, easier testing and simpler changes. Breaking a task into modules is called decomposition.

Lessons 5–6

5. Actuators and variables

An actuator carries out physical action. Examples include motors moving barriers and automatic doors. Sensors detect; actuators act.

A variable stores information that can change. If SpacesAvailable = 6, a successful entry reduces it to 5. A departure increases it again.

When the variable reaches zero, a decision can show FULL and prevent more entries. Limits stop the counter becoming negative or exceeding capacity.

Lesson 6

6. Seven-segment displays

A seven-segment display contains seven outputs (a–g). Switching the correct combination on produces a number.

The controller can select a pattern using the current value of a variable. To display more than one digit, it needs additional display positions.

Use the 7-Segment Lab to practise switching segments on and off.

Assessment skills

7. Testing and evidence

Dry run: trace a flowchart step by step. Test cases: choose normal, boundary and unexpected readings. Evaluation: explain what works and how it could be improved.

For a practical assessment, use screenshots of your own working flowcharts. Clearly annotate the inputs, outputs, subroutines, decisions and variables to explain your solution.

Test the normal case, a condition that is false, and what happens when a sensor fails.
