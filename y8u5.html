What is happening?

A write means placing a value into a list position. A swap is an exchange of two values. They measure different types of work, so do not compare them as if they were identical.

Year 8: Sorted! Revision Notes

These notes follow your learning journey from sorting everyday information to explaining algorithms. The interactive studio lets you test each method.

Lesson 1

1. Why do computers sort data?

A sorting algorithm is an ordered set of instructions that arranges items according to a chosen rule. Sorting can make information easier to find, present or compare.

Ascending: from smallest to largest, or A to Z. Descending: from largest to smallest, or Z to A.

Example: scores 31, 14, 26 become 14, 26, 31 (ascending) or 31, 26, 14 (descending).

Some text sorting systems treat uppercase and lowercase letters differently. The exact order depends on the chosen rules.

Lesson 1

2. Lists and algorithms

A list is an ordered collection of items. In Scratch, lists can be populated manually or imported from a plain text file with one value on each line. You can also export a list to save the values.

Algorithms need clear instructions. A comparison checks which value should come first; a swap exchanges two positions.

Bogo Sort: repeatedly shuffles randomly until the list happens to be sorted. It is unreliable and extremely inefficient for longer lists.

Empirical testing: run an algorithm on different data and measure what it does, rather than guessing.

Lesson 2

3. Bubble Sort

Bubble Sort checks pairs of adjacent values, left to right. In an ascending sort, if the left item is larger than the right one, swap them. Repeat across the list for multiple passes.

REPEAT enough passes: FOR each adjacent pair, left to right: IF left value > right value: SWAP the pair

A large value can move several places to the right in one pass. A small value can usually move only one place left in each pass.

Extension: An early-stop flag records whether any swaps occurred during a pass. No swaps means the list is sorted, so an optimised version may stop.

Lesson 3

4. Insertion Sort

Imagine ordering playing cards in your hand. The left part of the list is treated as sorted. Take the next item, compare it to earlier ones, shift larger items right and insert it into the right place.

FOR each item after the first: SAVE it as the key WHILE earlier items are too large: SHIFT those items right INSERT the key into the gap

Insertion Sort is especially effective when many items are already nearly in the correct order.

Lesson 3

5. Merge Sort

Divide and conquer: repeatedly split the list into smaller halves until each contains one item. Merge the sorted groups by repeatedly choosing the next value from the front of either group.

Example: [9, 3, 7, 2] splits into [9, 3] and [7, 2]. Sort the halves to [3, 9] and [2, 7], then merge to [2, 3, 7, 9].

Unlike Bubble Sort, Merge Sort does not depend on swapping neighbouring values. It uses temporary groups and writes values into the merged order.

Extension

6. Selection Sort

Keep a sorted section at the beginning of the list. Find the smallest remaining value and swap it into the next free position. Repeat until all positions are filled.

FOR each position in the list: FIND the smallest remaining value SWAP it into this position

In each pass, Selection Sort chooses a specific item from the whole unsorted section. Bubble Sort instead compares neighbours.

Key vocabulary

7. Know these words

  • Ascending: increasing order
  • Descending: decreasing order
  • Pass: one sweep through the part of a list being processed
  • Iteration: one repetition of instructions
  • Swap: exchange two values
  • Pseudocode: an informal way of writing algorithm steps
  • Nesting: placing one loop or decision inside another
  • Flag: a variable used to record that something happened
Skills and testing

8. How to earn explanation marks

  1. Give the method's name or purpose.
  2. Describe what it compares or moves.
  3. Explain how it repeats or finishes.
  4. Trace a small original example clearly.
  5. If comparing algorithms, use evidence from tests.

Useful tests: an unsorted list, an already sorted list, a reverse-sorted list and a list with duplicate values.

Important: Different implementations have different counts. An algorithm follows its programmed instructions, and does not magically change method midway through.
